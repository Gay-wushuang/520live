# MON-01 · Starry Luxe Clear V2 试点

**状态与范围。** `MON-01` 在状态矩阵中是“初始/掷骰可用”。本稿是 1440×1050 的状态画板，不是 1440×900 页面母版；不修改 React，也不声称 SVG 自带交互。初始数据采用当前 Store 的默认观众、位置索引 0（显示 #01）、第 1 回合、前进、1 骰、尚未掷骰。冻结稿中的“骰点：4 / 待执行”“当前 #02”及常驻“继续 / 下一回合”与初始运行时语义不一致，未继承。

## 结构

1. 顶部 58px 紧凑导航：项目身份、真实的积分抽奖入口、重置棋盘。
2. 行动区：观众/回合、位置、方向/骰数、轻立体骰子、单一主操作；相关状态归入同一个连续面板，未为每个数值单建卡片。
3. 28 格环形棋盘为最大主体；顺时针 #01～#28，各事件类型每隔 7 格重复。P1 位于 #01，结构容得下 P2；真正双棋子状态仍由 `MON-16` 负责。
4. 左侧仅有紧凑工具入口；底部状态条展示等待掷骰与无待处理事件。棋盘中心默认为空星夜背景，只留极少的低对比星点。

## 组件与视觉

主容器/行动区用深靛蓝，状态与操作统一用雾紫主按钮、深色次按钮、低饱和危险按钮。香槟金只用于当前位置和少量语义强调，不铺成大面积。七类棋格采用一致的图标方块、短名、格号和低饱和色；没有发光边框、玻璃叠层或多重描边。文字字号与颜色在 `design-tokens.json`。

## 被删除或合并的纯视觉元素

删去旧中心占位白框、常驻“当前棋盘”标题、重复规则说明、分散的数值小卡和无意义的空态骰点。当前状态信息合并到行动区与底部状态条。未删除真实功能：档案、观众编辑/添加/导入/删除、日志复制/CSV、七类图例在 `concepts/MON-01.tools-expanded.svg` 的可见展开稿中标注承载位置，**不是把隐藏的 `data-func` 算作功能覆盖**。

中心投掷反馈、事件提示、奖励反馈只在对应未来状态显示；本轮未绘制它们，也未实现动画。`MON-01.tools-expanded.svg` 是非正式状态映射的概念稿，静态标签“观众/记录/说明”只是建议的折叠入口，当前 React 没有这些抽屉触发器或新路由。

## 待运行时实施及风险

须在 React 中实现抽屉开合、焦点管理、窄屏响应、真实 28 格布局适配、状态驱动中心反馈、P2 棋子避让，以及真实数据对文本宽度的影响。`MON-DIRECTION` 在默认状态仅是状态标签；实际可选择方向按钮仅当对应效果生效后出现。`MON-ACTION-ROLL` 仍由当前 `waiting` 阶段启用规则控制。当前 SVG 的格子是静态视觉对象，不声称点击格子会触发事件。
