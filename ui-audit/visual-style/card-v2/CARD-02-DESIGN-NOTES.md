# CARD-02 V2.1 设计说明

状态基线：`b81c1d7589c535fedeb5bbe6bf364a7a23e0ba59`。`CARD-02` 是图片已载入、可抽取的桌面就绪态；不是旋转态或结果态。正式画板为 1440×1050。本轮仅修改 CARD V2 试点目录。

## 结构与视觉

- 顶部紧凑导航承载返回棋盘；左侧低频工具入口；轮盘占据主视觉；右侧单一连续面板承载一行档案摘要、状态、主按钮、反馈和独立重置；底部只保留一行收集摘要。观看顺序为轮盘 → 主按钮 → 状态反馈。
- 继承 MON-01 V2.1 的深靛蓝、雾紫、香槟金、圆角及按钮语法。四季各用一种低饱和辅助色，差异由扇区底色与真实卡牌图片共同表达；不使用高亮金线或粒子。
- 图片层来自 `public/春-积分卡.png`、`夏-积分卡.png`、`秋-积分卡.png`、`冬-积分卡.png`，构建时由项目现有 `sharp` 按 210×118、`contain` 生成确定性 JPEG 缩略图并内嵌。相对 V2 的 168×104，面积增加约 42%；不裁切原图主体。统一窄边框与极淡季节色覆盖层将插画融入扇区，不增加花纹或强光。这些图像不是重新绘制的奖励，也不是抽奖算法。
- “存档 1 · 玩家”、收集 0 张均是明确的静态设计示例；实际值需由 React 状态注入。

## 状态与交互边界

- `CARD-02.desktop`：就绪态，主抽取按钮可用；不显示结果卡。
- `CARD-02.LOADING`：卡图加载占位，主按钮禁用；示例状态，不声明新业务动作。
- `CARD-02.SPINNING`：主按钮与重置禁用，避免重复触发；旋转仅以静态状态文字表达，SVG 本身没有实现动画。
- `CARD-02.pointer-result-example`：额外的非运行时停靠概念，整盘旋转 −45°（等价 315°），春季扇区中心位于顶部固定指针下方；不是抽中春季的真实记录，也不是新的正式 CARD-02 状态。
- `CARD-02.error-proposal`：额外的未实现提案，展示图片加载失败时的错误反馈与禁用按钮。当前 `CardWheelPage.tsx` 捕获加载异常后会将 `isLoading` 置为 false，但没有单独错误 UI；因此不能宣称此画板与当前运行时一致，后续实施需要另行批准生产代码修改。
- `CARD-02.tools-expanded`：低频功能的概念抽屉，复用现有页面内行为，不创建新路由。左侧“收集／档案／记录”是同一抽屉的入口规划；点击后切换到相应分区，关闭后恢复轮盘主视图。存档删除等危险操作仍需现有确认逻辑。图中展示的是合并展开态，非已实现交互。
- 抽取完成后的结果、壁纸领取与终极奖励仍由原有 `ResultModal`、`WallpaperRewardModal`、`VideoRewardPlayer` 承载；本轮不制作虚构奖品画板。
- 返回棋盘与重置游戏分离。抽取资格仅跟卡图加载与旋转状态相关；画板未引入积分消耗或概率规则。

## 指针与概率边界

原始 Canvas 的扇区从正上方顺时针依次为春、夏、秋、冬，固定指针位于正上方。就绪态指针在边界，明确标作“待抽取”，不表示任何结果。设计示例的春季停靠角 315° 对应 `getWinningSegment(315) === 0`；其他扇区中心角分别为夏 225°、秋 135°、冬 45°。原始随机角生成器为四段各留 5° 边距，但 `useSpinController` 的额外圈数含非整数随机值，且叠加上次旋转角；因此当前运行时不能保证最终停靠远离边界。此问题只记录，不在 SVG 工作单中改算法、概率或结果状态机。

## 后续真实实现

本轮没有修改 React。若后续实施，需要将工具抽屉、统一样式和轮盘可视层接入现有组件，并保持 Canvas 指针、四季顺序、概率计算、存档与奖励状态机不变。静态 SVG 不代表这些交互已经实现。
