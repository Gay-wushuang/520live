# MON-01 · Starry Luxe Clear V2 试点

**状态与范围。** `MON-01` 在状态矩阵中是“初始/掷骰可用”。本稿是 1440×1050 的状态画板，不是 1440×900 页面母版；不修改 React，也不声称 SVG 自带交互。初始数据采用当前 Store 的默认观众、位置索引 0（显示 #01）、第 1 回合、前进、1 骰、尚未掷骰。冻结稿中的“骰点：4 / 待执行”“当前 #02”及常驻“继续 / 下一回合”与初始运行时语义不一致，未继承。

## 结构

1. 顶部 58px 紧凑导航：项目身份、真实的积分抽奖入口、重置棋盘。
2. 行动区：观众/回合、位置、方向/骰数、轻立体骰子、单一主操作；相关状态归入同一个连续面板，未为每个数值单建卡片。V2.1 等待态骰面使用无数值的横杠；只有结果样板显示示例点数。禁用按钮用独立低对比灰蓝填充，与可点击的雾紫主按钮区分。
3. 28 格环形棋盘为最大主体；顺时针 #01～#28，各事件类型每隔 7 格重复。P1 位于 #01，结构容得下 P2；真正双棋子状态仍由 `MON-16` 负责。
4. 左侧仅有紧凑工具入口；底部状态条展示等待掷骰与无待处理事件。棋盘中心默认为空星夜背景，只留极少的低对比星点。

## 组件与视觉

主容器/行动区用深靛蓝，状态与操作统一用雾紫主按钮、深色次按钮、低饱和危险按钮。香槟金只用于当前位置和少量语义强调，不铺成大面积。七类棋格采用一致的图标方块、短名、格号和低饱和色；没有发光边框、玻璃叠层或多重描边。文字字号与颜色在 `design-tokens.json`。

### 已评审后的微调

- 顶部导航高度由 58px 收至 54px，按钮同步压低 4px；副标题缩至 11px 并降为 68% 不透明度，主标题与操作仍清晰。
- 三张中心反馈卡由 543×248px 调至 520×230px，并略向上移；默认态仍无卡。反馈文本与待触发按钮同步重排，未改变状态或业务含义。
- 工具展开稿把当前观众行与“添加观众”操作略加强调；日志卡由 168px 收至 154px，图例保持一行可见但降为辅助信息。所有观众、档案、复制与 CSV 控件仍在可见区域内。

## 被删除或合并的纯视觉元素

删去旧中心占位白框、常驻“当前棋盘”标题、重复规则说明、分散的数值小卡和无意义的空态骰点。当前状态信息合并到行动区与底部状态条。未删除真实功能：档案、观众编辑/添加/导入/删除、日志复制/CSV、七类图例在 `concepts/MON-01.tools-expanded.svg` 的可见展开稿中标注承载位置，**不是把隐藏的 `data-func` 算作功能覆盖**。

中心投掷反馈与事件提示只在 `states/MON-01.ROLLING.svg`、`MON-01.ROLL_RESULT.svg`、`MON-01.EVENT_PENDING.svg` 三张**独立设计示例**中出现；默认 SVG 仍为空中心。三张图中的点数、目标格与事件均明确标记“设计示例”，不是截图或运行时结果，也未实现动画。反馈面板位于棋盘空心区域，不盖住格子或 P1。`MON-01.tools-expanded.svg` 是非正式状态映射的概念稿，静态标签“观众/记录/说明”只是建议的折叠入口，当前 React 没有这些抽屉触发器或新路由。

## 状态节奏建议（尚未实现）

| 设计稿 | 运行时关联 | 退出条件与注意 |
|---|---|---|
| READY | `gamePhase='waiting'`、`lastDiceResult=null` | 点击现有掷骰操作进入 rolling；中心不显示反馈。 |
| ROLLING | `isRollingDice=true`、`gamePhase='rolling'` | Store 当前约 1600ms 后产生点数；操作禁用，不建议在 SVG 中假定动画帧数。 |
| ROLL_RESULT | `lastDiceResult` 已赋值，随后由 `movePlayer` 进入 moving | 示例为从 #01 掷 4 点向 #05 移动。建议随移动过程短暂保留，移动结束后立即让位给待触发事件或等待态；具体淡出时长待 React/动效评审。它不是当前 Store 的独立稳定 `gamePhase`。 |
| EVENT_PENDING | `gamePhase='event'` 且 `pendingEvent` 存在、尚未打开事件弹窗 | 示例为从 #01 掷 1 点到 #02 厄运。保留现有“触发事件”动作，进入弹窗后移除中心提示。自动积分、厄运免疫等分支可能不进入此样板，须按真实状态判断。 |

## 工具区展开行为提案（非现有 React 功能）

左侧“观众”建议展开现有观众编辑、选择、添加、导入、删除与档案切换/保存/读取/新建；“记录”承载日志浏览、复制与 CSV；“说明”承载已有七类轮盘说明。展开稿以从左侧覆盖棋盘一部分的非破坏性抽屉示意：背板变暗，棋盘操作暂不可点，右上角 `×`、再次点入口、Esc 或点击背板关闭，关闭后恢复焦点和空中心。视觉上的关闭不应推进回合或改变 Store；是否采用覆盖式抽屉及键盘行为，须在 React 实施前确认。

操作成功/失败反馈建议在抽屉底部 `MON-FEEDBACK` 区域按状态显示，不能靠棋盘中心常驻提示；读取失败、导入无效、删除最后一位观众等异常需可读文本。禁用按钮须同时有状态文案而不只变暗。当前展开稿只是承载示意，**没有完成这些异常状态画板或真实交互**。

## 待运行时实施及风险

须在 React 中实现抽屉开合、焦点管理、窄屏响应、真实 28 格布局适配、状态驱动中心反馈、P2 棋子避让，以及真实数据对文本宽度的影响。`MON-DIRECTION` 在默认状态仅是状态标签；实际可选择方向按钮仅当对应效果生效后出现。`MON-ACTION-ROLL` 仍由当前 `waiting` 阶段启用规则控制。当前 SVG 的格子是静态视觉对象，不声称点击格子会触发事件。
