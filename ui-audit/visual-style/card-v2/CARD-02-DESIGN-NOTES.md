# CARD-02 V2 设计说明

状态基线：`CARD-02` 是图片已载入、可抽取的桌面就绪态；不是旋转态或结果态。正式画板为 1440×1050。当前仓库 HEAD 与冻结基线不是同一提交，本目录只新增 CARD 试点，不改既有画板。

## 结构与视觉

- 顶部紧凑导航承载返回棋盘；左侧低频工具入口；轮盘占据主视觉；右侧连续操作区承载档案摘要、阶段反馈、抽取条件、主按钮和重置；底部只保留收集摘要。
- 继承 MON-01 V2.1 的深靛蓝、雾紫、香槟金、圆角及按钮语法。四季各用一种低饱和辅助色，差异由扇区底色与真实卡牌图片共同表达；不使用高亮金线或粒子。
- 图片层来自 `public/春-积分卡.png`、`夏-积分卡.png`、`秋-积分卡.png`、`冬-积分卡.png`，构建时由项目现有 `sharp` 生成确定性 JPEG 缩略图并内嵌。它们是原图缩略图，不是重新绘制的奖励，也不是抽奖算法。
- “存档 1 · 玩家”、0/2 收集进度均是明确的静态设计示例；实际值需由 React 状态注入。

## 状态与交互边界

- `CARD-02.desktop`：就绪态，主抽取按钮可用；不显示结果卡。
- `CARD-02.LOADING`：卡图加载占位，主按钮禁用；示例状态，不声明新业务动作。
- `CARD-02.SPINNING`：主按钮与重置禁用，避免重复触发；旋转仅以静态状态文字表达，SVG 本身没有实现动画。
- `CARD-02.tools-expanded`：低频功能的概念抽屉，复用现有页面内行为，不创建新路由。左侧“收集／档案／记录”是同一抽屉的入口规划；点击后切换到相应分区，关闭后恢复轮盘主视图。存档删除等危险操作仍需现有确认逻辑。图中展示的是合并展开态，非已实现交互。
- 抽取完成后的结果、壁纸领取与终极奖励仍由原有 `ResultModal`、`WallpaperRewardModal`、`VideoRewardPlayer` 承载；本轮不制作虚构奖品画板。
- 返回棋盘与重置游戏分离。抽取资格仅跟卡图加载与旋转状态相关；画板未引入积分消耗或概率规则。

## 后续真实实现

本轮没有修改 React。若后续实施，需要将工具抽屉、统一样式和轮盘可视层接入现有组件，并保持 Canvas 指针、四季顺序、概率计算、存档与奖励状态机不变。静态 SVG 不代表这些交互已经实现。

生成：`python ui-audit/visual-style/card-v2/build_card02.py`；渲染：`node ui-audit/visual-style/card-v2/render_previews.mjs`。仅会写本目录的 `states/`、`concepts/`、`previews/`。
